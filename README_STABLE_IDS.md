# Тұрақты идентификаторлар және қауіпсіздік ережелері

`goal`: `weight_loss`, `muscle_gain`, `maintenance`, `endurance`.

`category`: `chest`, `back`, `legs`, `arms`, `shoulders`, `abs`, `cardio`, `full_body`.

Экрандағы атаулар қазақша. `StoredIds` бұрынғы орысша және қазақша мәндерді оқу кезінде таниды. Жаңа жазбалар тек тұрақты ID-лерді сақтайды. Ескі тарих жазбалары өзгертілмейді; олардың ID-лері, күндері, ұзақтығы мен саны сақталады. Профильді сақтау және салмақ жазу кезінде ескі мақсат тұрақты ID-ге ауысады. Салмақ транзакциясында мақсат қайта оқылады, сондықтан қатар өзгертілген мақсат басылып жазылмайды.

## Жариялау
Жергілікті файлды өзгерту бұлттағы ережелерді автоматты түрде жаңартпайды. Firebase Console → Firestore Database → Rules бөлімінде түбірдегі `firestore.rules` толық мәтінін жариялаңыз. Содан кейін жаңа APK орнатыңыз. Бұрынғы қосымша нұсқалары тілге тәуелді мәндерді жазса, жаңа ережелер ол жазбаларды қабылдамайды; жаңартылған APK қолданыңыз. Ескі деректерді оқу рұқсаты сақталған. Жаппай дерек көшіру не жою қажет емес.

## Тексеру
- Android: `powershell -ExecutionPolicy Bypass -File .\build-fit.ps1`.
- Қауіпсіздік тесттеріне тәуелділіктерді `tests/firestore` қалтасында `npm ci` арқылы орнатыңыз (npm кэшін D: дискіне бағыттаңыз).
- Эмулятор: `powershell -ExecutionPolicy Bypass -File .\test-firestore.ps1`.

Тесттер `demo-fit-rules` жергілікті жобасымен ғана жұмыс істейді. Нақты Firebase деректеріне қосылмайды және ережелерді жарияламайды. Эмуляторда серверлік уақыт, иесінің рұқсаты, басқа пайдаланушы мен тіркелмеген сұраулар, өрістер/типтер/диапазондар, ескі деректер, ID сәйкестігі, профиль сақтау, салмақ транзакциясы және жаттығуды қайталап сақтау тексеріледі.

Жаңа уақыт белгілері серверлік болуы керек (`FieldValue.serverTimestamp()`); профильдің тіркелу уақыты мен email өзгермейді. Жаттығу және салмақ тарихының дайын жазбаларын өзгерту/жоюға тыйым салынған. Кез келген басқа жол әдепкі бойынша жабық.
